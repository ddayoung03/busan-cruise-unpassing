# 역할별 AI 세션 세팅과 시작 프롬프트

2026.11.17 · 크루즈 미식 루트 팀

크루즈 미식 루트 팀(4인)이 각자 AI 세션을 만들 때 그대로 복사해 쓰는 설정과 프롬프트다. 공통 컨텍스트를 먼저 붙이고, 자기 역할의 시작 프롬프트를 이어서 보낸다.

## 0. 공통 세팅

AI는 각자 쓰던 것을 그대로 쓴다. 아래 프롬프트는 ChatGPT·Gemini·Claude 어디에 넣어도 똑같이 동작하고, 도구마다 다른 건 '자료와 지침을 계속 기억시켜 두는 곳'뿐이다. 역할마다 그런 공간을 하나씩 만들고, 공통 자료를 올린 뒤 시작한다. (메뉴 이름은 버전마다 조금 다를 수 있다.)

| AI | 세션 만드는 곳 | 컨텍스트·자료 넣는 곳 | 참고 |
| --- | --- | --- | --- |
| ChatGPT | 프로젝트(Projects) 새로 만들기 | 프로젝트 지침에 컨텍스트, 프로젝트 파일에 자료 | 검색을 켜고 출처 확인. 코드를 자체로 실행해 볼 수 있지만 최종 코드는 Colab에서 돌린다 |
| Gemini | Gem 만들기 | Gem 지침에 컨텍스트, 지식(파일)에 자료 | Colab 안의 Gemini로 코드 셀을 바로 고칠 수 있어 A·B·C에 편하다 |
| Claude | 프로젝트 만들기 | 프로젝트 지침에 컨텍스트, 프로젝트 지식에 자료 | 웹 검색 켜기 |
| NotebookLM | 노트북 만들기 | 소스에 기사·문헌·유튜브 링크 | 올린 자료 안에서만 답하고 인용을 달아 줘서 C(서사 검증)·D(기사 근거)에 추천. 코드용은 아니다 |
| 프로젝트 기능이 없을 때 | 일반 새 대화 | 첫 메시지에 컨텍스트 + 역할 프롬프트 + 파일 첨부 | 대화가 길어지면 마무리 프롬프트로 요약받고, 그 요약을 붙여 새 대화를 연다 |

**파일 주의**: HWP는 대부분의 AI가 제대로 못 읽는다. 공고문은 한글에서 PDF로 저장해 올린다. docx·pdf·csv·png·py는 그대로 올려도 된다.

| 항목 | 설정 |
| --- | --- |
| 세션 이름 | `아이디어톤-A 데이터` / `-B 모델` / `-C 서사` / `-D 총괄` |
| 공통 자료(모두) | 2주차 팀활동보고서 v3, 기획 요약 문서(PDF로 내보내기), 역할분담 이미지, 공고문 PDF(심사 기준), 2주차 수업 메모 |
| 역할별 추가 자료 | 각 역할 섹션에 적음 |
| 켜둘 기능 | 웹 검색(출처 확인용) |
| 코드 실행 | AI가 준 코드는 각자 Colab 노트북에서 실행하고, 결과나 에러를 다시 붙여넣는다 |
| 결과 공유 | Google Drive 팀 폴더(01_원천데이터 ~ 05_문서) |

역할이 다른 AI를 써도 되지만, 파일 형식(CSV 열 이름)은 아래 프롬프트에 적힌 대로 맞춘다. 그래야 다른 사람 AI가 만든 파일을 바로 읽는다.

세션의 지침(instructions) 칸에, 지침 칸이 없으면 첫 메시지에 아래 컨텍스트를 그대로 붙여넣는다. 그다음 자기 역할의 시작 프롬프트를 보낸다.

```text
[프로젝트 컨텍스트]
- 대회: 2026 제1회 인문·사회·수리 융합 지·산·학 아이디어톤 "부산의 맛, 로컬에서 글로컬" (부산대).
  심사: 인문학적 해석 / 사회과학적 검증 / 산업수학적 모델링 / 지산학 연계·실현 가능성 / 완성도 각 20점.
- 우리 주제: 크루즈 관광객 미식 루트 최적화.
  부산항 크루즈 승객은 대부분 기항(아침 입항, 저녁 출항)이라 4~8시간만 머물고,
  부산의 맛을 못 먹고 떠난다('부산 패싱').
  해결: 터미널(북항·영도)에서 출발해 승선 마감 30분 전에 돌아오는 루트를
  시간창 오리엔티어링 문제(OPTW)로 계산하고, 같은 입항 정보로 상인에게 수요 예보를 준다.
- 핵심 개념:
  · 퍼널: 입항 → 상륙 → 부산 내 결제 → 음식업종 → 대표음식·전통시장
  · 대조군: 제주·인천 기항지, 부산 내 비기항일·터미널에서 먼 구, 전년 동월 대비(YOY)
  · 대기 추정 = 피크 대기 × 시간대 혼잡계수 × 크루즈 가중
  · 확산: 분산 배정 → 원거리 1곳 슬롯·터미널 팝업 → 모항 승객
- 일정: 11/20(금) 3차시 중간 점검, 11/27(금) 최종 발표.
- 팀 4명: A 데이터·사회검증 / B 수리모델·코드 / C 인문서사·텍스트분석 / D 총괄·발표·지산학.
- 도구 제약: Google Colab에 기본 설치된 것만 사용
  (pandas, numpy, scipy, matplotlib, seaborn, folium, openpyxl). 공유는 Google Drive.

[너에게 바라는 작업 방식]
1. 모르는 수치·사실은 지어내지 말고 [확인 필요]로 표시해. 출처가 있으면 URL을 같이 줘.
2. 답은 결론 먼저, 근거는 그다음. 질문에는 짧게라도 꼭 답해.
3. 코드는 Colab에 그대로 붙여 넣어 돌아가게, 셀 단위로 나눠서 주고 각 셀이 무엇을 하는지 한 줄로 적어.
4. 내가 파일을 주면 먼저 df.head()·df.info()로 구조를 확인하는 코드부터 주고, 그 결과를 본 뒤에 다음 단계로 가.
5. 어떤 분석 기법을 쓸 때는 기법 이름, 한 줄 설명, 참고할 예제를 먼저 보여주고 우리 문제에 적용해.
```

## C. 인문 서사·텍스트 분석

**목표**: 노드별 서사 카드와 국적별 선호 가중치를 만들고, 공감 서사를 발표용으로 다듬는다.

- **추가로 올릴 자료**: `food_nodes_assumed.csv`(노드 목록과 현재 서사 태그), 1주차 부산 밀접성 점수표, '리센느 서사' 수업 메모
- **작업 공간**: 서사는 Google Docs, 리뷰 분석은 Colab `03_리뷰분석_C.ipynb`
- **넘겨줄 것**: 국적별 가중치·피크 대기 → B, 서사 카드·공감 서사 → D

```text
너는 디지털 인문학 연구자이자 텍스트 마이닝 조수야. 나는 팀에서 C(인문 서사·텍스트 분석)를 맡았고,
심사 항목 '인문학적 해석(문화·역사적 이해, 새로운 접근방식)'을 책임져.

[내 작업]
1. 서사 검증: 첨부한 노드 목록의 서사 태그(피란·항구·교류·근대)가 사실인지 확인해줘.
   예: 밀면은 피란민이 메밀 대신 밀가루로 만들었다, 부평깡통시장은 미군 통조림 물자에서 이름이 왔다.
```

## 세션 마무리와 AI 사용 규칙

작업을 끝낼 때마다 아래 프롬프트를 보내고, 나온 결과를 Drive 폴더 README에 붙여넣는다. 다음 날 새 대화를 열 때는 이 요약을 첫 메시지로 다시 붙이면 이어서 할 수 있다.

```text
오늘 작업을 정리해줘. 형식은 아래 그대로.
1. 한 일 (3줄 이내)
2. 만든 파일 이름과 들어있는 내용 (파일마다 한 줄)
3. 아직 [확인 필요]로 남은 것
4. 다른 팀원에게 넘길 것 (누구에게, 무엇을, 어떤 형식으로)
5. 내일 할 일 (우선순위 순)
```

**팀 공통 규칙**

1. AI가 낸 숫자는 출처를 눈으로 확인한 뒤에만 보고서·발표에 넣는다. 출처가 없으면 '가정' 또는 '추정'이라고 적는다.
2. 코드는 반드시 Colab에서 돌려 본다. 에러는 전문을 그대로 AI에게 붙여넣는다.
3. 분석 기법은 이름 → 예제 → 우리 데이터 순서로 물어본다(수업 팁, 엉뚱한 답을 줄이는 방법).
4. 다른 사람 노트북은 사본으로만 연다. 파일 이름은 `내용_날짜_역할.확장자`.
5. 사람 이름·연락처·학번 같은 개인정보는 AI에 올리지 않는다(인터뷰 내용은 이름을 지우고 올린다).
6. AI가 쓴 문장은 그대로 내지 않고, 마지막에 사람이 읽고 고친다. 발표에서 설명할 수 없는 내용은 뺀다.
