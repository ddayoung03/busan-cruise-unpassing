2026-11-18. 지정된 리뷰·코드 2개·CSV 3개를 정적으로 검토했다. `run_B_model.py` 및 모델·테스트는 실행하지 않았다. 아래 R2 번호는 2차 보고서의 핵심 문제 8건이다. **복귀 지각 0%와 전체 실행가능성은 다르다:** 저장 결과의 전체 준수율은 92.1%, 식사 위반율은 7.9%다.

## R2 지적사항 판정

1. **fixed** — 섭취 시작 기준으로 줄 서기 시각을 찾도록 변경했다(`cruise_route_optw.py:165`); 연속시간 정확성이 아닌 1분 탐색이다.
2. **partly** — 줄 서기 기준·공동 반복평가·시간표 보존을 추가했으나 수렴 판정의 경계 문제가 남고, +8분 분산 CSV는 여전히 4/6그룹 위반이다.
3. **fixed** — 고정 시간표 위험도가 공통 평가기를 사용해 영업·포만·식사·경로 제약과 추가 대기를 반영하고 규칙별 위반율을 출력한다.
4. **partly** — 두 선박 공동평가·인원 가중·실패 인원 분리를 추가했으나 비수렴 결과도 집계 가능하고 선석 통합·처리용량 가정은 남는다.
5. **partly** — 평가기의 방문 수·필수 원거리 검사와 탐욕의 대기 선택은 수정; 탐욕은 필수조건 실패를 표시만 하고 여전히 ‘같은 제약’ 결과로 반환한다.
6. **not fixed(수정 확인 불가)** — A 코드·월별 자료·퍼널은 이번 지정 범위 밖이므로 R2 문제의 해소를 확인할 근거가 없다; 실제 미수정 단정은 아니다.
7. **partly** — 7시간 예산 별도 평가를 추가했다(`run_B_model.py:149`); 서사 카드 문구·루트 2·3 및 새 서사 검증 CSV는 이번 범위에서 확인하지 않았다.
8. **partly** — 브레이크 입력·체류 겹침 검사는 추가했으나 재개장까지 기다리는 후보가 빠져 있다; N16 입력값·휴무 반영은 지정 파일만으로 확인하지 않았다.

## 추가 핵심 문제

1. **[높음] 재개장 대기 누락 — `03_코드/cruise_route_optw.py:190`, `:204`.** 최초 후보가 브레이크와 겹치면 버릴 뿐 `break_end`부터 다시 찾지 않는다. 예컨대 비식사 노드에 15:10 도착, 15~17시 브레이크, 대기 0이면 17시 방문이 가능해도 후보가 없다(90분 경계 탐색으로도 누락). **수정:** 영업 구간마다 최초 가능 시각을 생성하고 평가기에도 동일 적용.
2. **[높음] 수렴 판정·사용 조건 불충분 — `03_코드/cruise_route_optw.py:442`, `03_코드/run_B_model.py:132`.** 시각 변화가 0.5분 미만이어도 30분 겹침 경계를 넘으면 혼잡 가산이 불연속적으로 바뀐다. 또한 상인 예보는 `converged=False`라도 `feasible`만으로 집계한다. **수정:** 최종 시각으로 재평가해 겹침 관계·대기·제약의 일치를 확인하고 비수렴은 별도 실패 처리. 현재 CSV의 True만으로 이 검증을 대체할 수 없다.
3. **[중간] 실패 배정이 후속 지표에 포함 — `03_코드/run_B_model.py:106`, `:111`.** +8분 분산은 4/6그룹이 위반인데 확산 지출·추천빈도에는 여섯 경로 전체가 들어간다. 실행 가능한 방문·지출로 읽으면 과대 해석된다. **수정:** 계획 기준임을 표에 명시하고 실행가능 그룹 기준 지표·탈락 인원을 별도 출력.
4. **[중간] 실행가능 해 없음 처리 누락 — `03_코드/cruise_route_optw.py:401`, `:419`.** 혼잡이나 촉박한 마감으로 `solve()`가 빈 목록을 반환하면 `[0]`에서 중단돼 실패 그룹을 보존하지 못한다. **수정:** 해 없음 상태를 명시적으로 반환·집계하고 재배정 실패가 전체 산출을 중단하지 않게 한다.
