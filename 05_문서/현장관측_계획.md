# 현장 관측 계획 — 점포 5곳 대기열 실측

교수님 피드백 반영:
- 점포 5곳에서 시간대별 도착, 처리 시작·종료, 창구 수, 퇴장 시각을 기록한다.
- 기항일과 비기항일의 차이는 일별 판매 기록이나 현장 관측으로 비교한다.

## 왜 하나
- 모델의 줄 대기 시간, 좌석·창구 수, 점심 가동률은 지금 **추정·가정**이다.
- 관측하면 다음 값을 실제로 잴 수 있다.
  - 도착률 λ
  - 처리율 μ
  - 창구 수 c
  - 대기
  - 시간당 수용 인원
- 잰 값을 모델(`food_nodes`의 `cap_hour`, `wait_peak_min`)에 넣으면, 핵심 질문인 **"점포를 돌고 승선 마감 30분 전까지 돌아올 수 있나"**를 실측값으로 다시 확인할 수 있다.

## 언제
- **같은 요일 2일**: 크루즈 기항일 1일 + 기항 없는 날 1일
  - 관측일 후보: `python 03_코드/analysis_F_observation.py --plan <스케줄 CSV>`
  - 스케줄 파일: 공공데이터포털 15164308 「부산광역시_크루즈 선석스케줄 정보」(API, 활용신청 승인됨)
- **시간**: 10:30~14:30. 점심 피크를 포함하고, 크루즈 승객이 원도심에 오는 시간대다.
- **인원**: 점포당 1명. 5명이 동시에 관측하고, 사람이 부족하면 2곳씩 나눠 2회 관측한다.

### 관측일 (확정, 2026-11-23 갱신)
부산광역시 크루즈 선석스케줄(공공데이터포털 15164308, 기준일 2026-08-27, `01_원천데이터/data.go.kr/크루즈선석스케줄_부산시_15164308.csv`)로 정했다. `python 03_코드/analysis_F_observation.py --plan <이 CSV>` 결과(앞으로 6주 안 승객 많은 기항일과 같은 요일 비기항일 짝)를 따른다.

| 회차 | 날짜 | 그날 크루즈 | 쓰임 |
|---|---|---|---|
| 사전 관측 1 | **11.23(월)** | 없음 | 기록지·절차 시험 + 월요일 짝의 비기항일 |
| 사전 관측 2(최종 발표 전) | **11.24(화)** | STAR NAVIGATOR 3,044명(북항 09~20시) + EASTERN VENUS 500명(국제여객터미널) | 첫 기항일 실측값 |
| 본 관측 A | **11.28(토)** ↔ **12.5(토)** | 11.28 SPECTRUM OF THE SEAS 5,622명(북항 07~18시) / 12.5 없음 | 북항 대형선 = 시나리오 S1과 같은 조건. 같은 요일 짝 |
| 본 관측 B | **11.30(월)** ↔ 11.23(월) | 11.30 ADORA MAGIC CITY 5,246명(영도 10~22시) / 11.23 없음 | 11.23 사전 관측을 비기항일로 재사용 → 하루만 더 나가면 짝 완성 |
| 예비 | 12.4(금) ↔ 12.18(금) | 12.4 ADORA MAGIC CITY 5,246명 / 12.18 없음 | A·B 중 하나를 못 하면 대신 |

- **화·목은 짝이 안 된다**: 12월 화·목에는 EASTERN VENUS(500명, 국제여객터미널)가 거의 매번 들어와 비기항일이 없다. 그래서 잠정안(12.1·12.8 화)을 토·월 짝으로 바꿨다.
- **관측 시간**: 07시 북항 입항(11.28)은 10:30~14:30. 10시 영도 입항(11.30, 12.4)은 승객이 원도심에 늦게 오므로 11:00~15:00.
- **전날 확인**: 자료 기준일이 2026-08-27이라 바뀔 수 있다. 부산항만공사 홈페이지 → 정보공개 → 「크루즈 입항스케줄」에서 전날 입항 여부·접안 시각을 확인하고 기록지 비고에 선박명을 적는다.

## 무엇을 (한 줄 = 한 일행)
기록지: `05_문서/현장관측_기록지.csv`를 복사해 `01_원천데이터/현장관측/관측_날짜_점포.csv`로 저장한다.

| 열 | 적는 법 |
|---|---|
| 날짜 | 2026-11-28 |
| 기항일 | Y / N |
| 점포ID | N06, N04, N05, N08, N07 |
| 일행번호 | 1, 2, 3 … (그날 점포마다 새로) |
| 인원 | 일행 인원 수 |
| 도착 | 줄 끝에 선 시각 (HH:MM) |
| 처리시작 | 주문하거나 자리에 앉은 시각 |
| 처리종료 | 포장은 음식을 받은 시각, 식당은 식사를 마친 시각 |
| 퇴장 | 가게를 떠난 시각 |
| 창구수 | 그 시각에 열려 있던 주문 창구·테이블 수 |
| 크루즈승객 | Y / N / ? (명찰·크루즈 가방·언어로 추정, 모르면 ?) |
| 비고 | 단체, 줄 포기 등 |

- 개인을 알아볼 수 있는 정보(사진, 이름)는 적지 않는다.
- 줄을 포기하고 떠난 일행은 처리시작을 비우고 비고에 '포기'라고 적는다.
- 사장님께 관측 취지를 먼저 말씀드리고 허락을 받는다.

## 관측 뒤
```bash
python 03_코드/analysis_F_observation.py     # → 02_정제데이터/현장관측_추정_F.csv, 현장관측_기항일비교_F.csv
```
- **점포·시간대별 추정값**: λ, 평균 처리 시간, c, 가동률 ρ, 관측 대기, Erlang C 예측 대기, 시간당 수용 인원
- **기항일 vs 비기항일**: 점포별 평균 대기 차이와 Welch t (표본이 작으면 참고용)
- **모델 반영**: `food_nodes_1118_B.csv`에 `cap_hour`(시간당 수용 인원)와 `wait_peak_min`(점심 관측 대기)을 넣고 `run_B_model.py`, `make_service_routes.py`를 다시 실행한다.
- **추정식 점검**: `--selftest`(가상 표본)로 추정식이 이론값과 맞는지 확인했다.
